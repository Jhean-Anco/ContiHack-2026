# Game design document (GDD)

## Estado y fantasía

GDD inicial, no contenido implementado. El jugador explora una representación ficticia y respetuosa de un entorno inspirado en Huancayo y ayuda a personajes a resolver problemas. Lugares, prácticas, relatos, lengua y símbolos requieren contraste con fuentes locales y personas conocedoras; evitar afirmar exactitud etnográfica o turística.

Alcance confirmado del PMV: grados 1.º–5.º de Secundaria; Ciencias Sociales (historia de Huancayo) y Matemática; entorno interactivo dentro de un máximo de cuatro manzanas recorridas desde Plaza Constitución. La estructura recomendada para prototipar está en [concepto PMV](concepto-pmv.md).

## Core loop

Explorar → conversar/recibir contexto → elegir misión → resolver reto → recibir feedback → reintentar/reflexionar → cerrar misión y recibir recompensa lúdica → elegir siguiente ruta. Debe ser entendible, corto, interrumpible y usable con teclado/táctil.

## Jugador y NPC

El estudiante controla un avatar de personalización neutral, sin datos sensibles ni elección que requiera revelar identidad. NPC guía narrativa y no solicita información personal, contacto, ubicación real, fotos ni secretos. Diálogos breves, comprensibles, editables y revisables culturalmente.

## Misiones, retos y feedback

La misión da propósito; el reto define objetivo interno, instrucción, interacción, respuestas válidas, evidencia, errores previsibles, feedback, apoyos y trazabilidad curricular. Presentar una tarea a la vez y permitir pausa/salida. Feedback específico y no punitivo; véase [evaluación formativa](../01-pedagogia/evaluacion-formativa.md).

## XP, desbloqueos y reglas

XP recompensa acciones de juego, nunca significa aprendizaje o dominio. Las recompensas son cosméticas/narrativas; no hay compras, moneda canjeable, cajas aleatorias ni presión por racha. No cerrar acceso a prácticas esenciales por rendimiento o XP. Las reglas del juego deben estar explicadas, consistentes, reversibles y probadas.
