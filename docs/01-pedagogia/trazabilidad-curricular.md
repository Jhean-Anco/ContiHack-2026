# Trazabilidad curricular

## Cadena auditable

`fuente oficial/versionada → elemento oficial cotejado → interpretación revisada → objetivo interno del reto → acción/respuesta observable → criterio/feedback → evidencia de revisión`.

Cada transición tiene un ID y evidencia; no basta con asignar el nombre de un área, poner el grado en una etiqueta o mencionar “CNEB”. La historia de Huancayo como tema no prueba por sí sola correspondencia con Ciencias Sociales, y usar un mapa no demuestra por sí mismo una competencia matemática.

## Registro por relación

| Campo | Contenido requerido |
|---|---|
| Fuente | Entidad, documento, norma, edición/versión, URL, fecha de consulta y localizador preciso. |
| Elemento curricular | Tipo y denominación literal cotejada. Diferenciar cita de paráfrasis. |
| Reto | ID y versión, grado, objetivo interno, instrucción, respuesta/evidencia y criterio. |
| Relación | Directa, contextual o pendiente, con explicación de por qué el reto sí o no evidencia el elemento. |
| Revisión | Nombre/rol competente, fecha, decisión, observaciones y referencia a la evidencia. |
| Estado | `pendiente_validacion`, `verificado_documentalmente`, `revision_especialista`, `aprobado_para_uso` o `retirado`. |

## Publicación y cambios

Bloquear afirmaciones de alineación en contenido/marketing si el elemento, interpretación o reto están pendientes. Conservar versión previa y registrar fecha, causa, documentos afectados, tareas de revalidación y aprobador en el [changelog curricular](../09-referencias/changelog-curricular.md). Si la norma o fuente cambia, suspender el mapeo afectado hasta revisar su vigencia e impacto. El estado del producto hoy es **sin mapeos de retos aprobados**.
